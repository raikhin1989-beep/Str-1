# Архитектура

Карта того, что где живёт на сервере. Сервер общий с соседним проектом
[`raikhin1989-beep/Str`](https://github.com/raikhin1989-beep/Str) — разделение путей
описано в `CLAUDE.md` и здесь не пересматривается, а только дополняется.

## Домен

`https://raikhinwhiskey.duckdns.org/` — секрет `DUCKDNS_SUBDOMAIN` = `raikhinwhiskey`
(без суффикса `.duckdns.org`). Поддомен регистрируется вручную в веб-интерфейсе
DuckDNS: API умеет только обновлять IP у уже существующего имени, создавать новые не умеет.

Запасной вход `http://<SERVER_HOST>:8081/` остаётся и работает, даже если домен,
сертификат или конфиг соседа сломались.

## Что кому принадлежит

| | `Str` (сосед) | Этот репозиторий |
| --- | --- | --- |
| Докрут статики | `/var/www/html` | `/var/www/str-1` |
| Конфиг веб-сервера | `/etc/caddy/Caddyfile` | `/etc/caddy/str-1.caddyfile` + `/etc/caddy/sites.d/str-1.caddy` |
| Службы | `caddy.service` | `str-1-site.service`, `str-1-app.service`, `str-1-backup.timer` |
| Порты | 80, 443 | 8081 (наружу), 8082 (только localhost) |
| Код приложения | — | `/opt/str-1/app`, venv `/opt/str-1/venv` |
| База | — | `/var/lib/str-1/app.db` |
| Бэкапы | — | `/var/backups/str-1/` |

**База лежит вне докрута намеренно.** Деплой синхронизирует `site/` в `/var/www/str-1`
с `--delete`: всё, что окажется в докруте и не придёт из репозитория, будет стёрто
следующим выкатом. `/var/lib/str-1/` rsync не трогает.

## Маршрутизация запросов

Оба экземпляра Caddy — свой на 8081 и основной на 443 — получают одинаковую логику:

```
/healthz, /version          → файлы из /var/www/str-1 (контракт проверки деплоя)
/static/*, /robots.txt,
/favicon.ico                → файлы из /var/www/str-1
/*                          → reverse_proxy 127.0.0.1:8082
502, 503, 504               → /index.html из /var/www/str-1 (запасная страница)
```

`healthz` и `version` остаются статикой сознательно: по ним проверяется, что деплой
доехал. Если бы их отдавало приложение, падение приложения выглядело бы как
провалившийся деплой, а упавший деплой — как падение приложения.

Приложение слушает только `127.0.0.1` — снаружи в него нельзя постучаться мимо Caddy.

## Состав приложения

| Слой | Чем |
| --- | --- |
| HTTP | FastAPI + uvicorn |
| Шаблоны | Jinja2, серверный рендеринг |
| Клиентский JS | Ванильный, без сборки. Экран ведущего и страница гостя опрашивают сервер раз в 3 секунды: раунд открывает ведущий, а гость смотрит в телефон |
| Хранилище | SQLite, режим WAL |
| Распознавание виски | Yandex AI Studio (текст) и Vision OCR (этикетка на фото) или Anthropic `claude-opus-5` (текст и фото), кэш в БД. Выбор — по доступности с сервера, см. `docs/PLAN.md` |
| Телеграм | Bot API, вебхук на секретном пути. Исходящие с сервера не проходят — итоги развозит раннер GitHub, см. `docs/RUNBOOK.md` |
| Тесты | pytest, прогон в CI до выката |

Фронтенд-сборки нет намеренно: на сервере не появляется ни node, ни npm,
а деплой остаётся тем же самым rsync плюс перезапуск службы.

Стили и скрипты лежат в `site/static/`, а не в `app/`: их отдаёт Caddy прямо
из докрута, минуя приложение, и отдельный шаг копирования не нужен — они
приезжают тем же rsync, что и остальная статика.

## Секреты

Задаются в Settings → Secrets and variables → Actions. В логи не выводятся никогда —
только факт наличия и длина.

| Секрет | Для чего | Обязателен |
| --- | --- | --- |
| `SERVER_HOST`, `SERVER_PASSWORD` | Доступ к серверу | да |
| `SERVER_USER`, `SERVER_PORT` | По умолчанию `root` и `22` | нет |
| `DUCKDNS_SUBDOMAIN`, `DUCKDNS_TOKEN` | Домен и сертификат | для HTTPS |
| `ADMIN_PASSWORD` | Вход в админку | да |
| `ANTHROPIC_API_KEY` | Распознавание виски — только с хостинга вне РФ | нет |
| `YANDEX_API_KEY` | Распознавание виски через Yandex AI Studio | для распознавания |
| `YANDEX_FOLDER_ID` | Каталог Yandex Cloud, нужен вместе с ключом | для распознавания |
| — | Роль `ai.vision.user` у сервисного аккаунта **и** область действия `yc.ai.vision.execute` у API-ключа — без любого из двух чтение этикетки отвечает 403 | для фото |
| `AI_PROVIDER` | Явный выбор провайдера: `yandex`, `anthropic` или `off` | нет |
| `AI_PHOTO` | Ручное переопределение: `on` — показать загрузку фотографии несмотря на отказ OCR, `off` — спрятать даже там, где работает. Не задан — решает сам сайт, спросив у Vision OCR | нет |
| `TELEGRAM_BOT_TOKEN` | Бот `@raikhinwhiskey_bot` | для привязки и рассылки |
| `TELEGRAM_WEBHOOK_SECRET` | Секрет вебхука: латиница, цифры, `_` и `-`, до 256 символов | для привязки и рассылки |

Отсутствие необязательного секрета не должно ронять деплой: функция выключается,
в лог пишется предупреждение, остальной сайт работает. Так уже сделано для DuckDNS
и для админки — без `ADMIN_PASSWORD` она отвечает 503, остальной сайт живёт.

Секреты приложения деплой кладёт в `/etc/str-1/app.env` (владелец `root:str1`,
права 640) и подключает к службе через `EnvironmentFile`. Не через аргументы
командной строки: они видны в `/proc` любому пользователю системы.

## Порядок выката

1. pytest — красные тесты означают, что деплоя не будет;
2. rsync `site/` → `/var/www/str-1` (с `--delete`);
3. rsync `app/` → `/opt/str-1/app`, установка зависимостей в venv;
4. запись обоих конфигов Caddy, `caddy validate` **объединённой** конфигурации соседа;
5. перезапуск `str-1-app.service`, перезагрузка обоих Caddy;
6. проверка снаружи: `/healthz`, ответ приложения, оба входа;
7. **последним шагом** запись SHA в `/var/www/str-1/version`.

Порядок важен: свежий SHA в `version` означает, что прогон дошёл до конца,
а не только выложил файлы.
