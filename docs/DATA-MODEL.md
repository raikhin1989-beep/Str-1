# Модель данных

SQLite, файл `/var/lib/str-1/app.db`, режим WAL. Схема создаётся миграциями
(нумерованные sql-файлы), откат — восстановлением из бэкапа.

## Таблицы

### `tasting` — дегустация

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `title` | text | «Дегустация 8 августа» |
| `held_on` | date | |
| `status` | text | `draft` → `registration` → `round_nose` → `round_palate` → `scoring` → `closed` |
| `category_level` | text | `class` или `region` — гранулярность частичных баллов |
| `created_at` | datetime | |

Статус — это машина состояний, а не свободное поле. Раунд по вкусу не открывается,
пока не закрыт раунд по запаху; итоги не считаются, пока открыт любой раунд.

### `whisky` — справочник

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `name` | text | «Aberlour 13 Double Cask» |
| `distillery` | text | |
| `wclass` | text | односолодовый скотч / купажированный скотч / односолодовый (не Шотландия) / бурбон / теннесси / ржаной / прочее |
| `region` | text | Speyside, Highland, Tennessee… |
| `abv` | real | крепость, % |
| `age_years` | int | null для без возраста (NAS) |
| `cask` | text | тип бочки |
| `grain` | text | сырьё: ячменный солод, кукуруза, рожь… |
| `filtration` | text | холодная фильтрация: да / нет / неизвестно |
| `price_rub` | int | ориентировочная цена |
| `colour`, `nose`, `palate`, `finish` | text | цвет и ноты |
| `source` | text | `manual` (введено админом) или `ai` (получено моделью) |
| `created_at` | datetime | |

Одна таблица и для «того, что наливаем на конкурсе», и для «того, что нашли по
фото». Разница — в `source`: на публичной карточке у записей `ai` стоит пометка
«данные ориентировочные».

### `tasting_whisky` — что наливается на конкретной дегустации

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `tasting_id` | fk | |
| `whisky_id` | fk | |
| `sample_no` | int | номер образца, 1..N |

Уникальность: `(tasting_id, sample_no)` и `(tasting_id, whisky_id)`.
Кнопка «перемешать» переназначает `sample_no` и доступна только пока
дегустация в `draft` или `registration`.

### `participant` — участник

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `tasting_id` | fk | |
| `name` | text | |
| `join_token` | text unique | в ссылке участника и в deep link телеграма |
| `tg_chat_id` | int | заполняется после нажатия Start у бота |
| `contact` | text | Куда прислать ссылку: телеграм, телефон, почта — свободный текст. Не проверяется: нужен ведущему, а не приложению |
| `tg_username` | text | справочно |
| `created_at` | datetime | |

`tg_chat_id` — единственный способ написать человеку в телеграм: по `@username`
Bot API отправлять не умеет. Пока поле пусто, итоги приходят только на сайте.

### `answer` — ответ участника в раунде

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `participant_id` | fk | |
| `round` | text | `nose` или `palate` |
| `sample_no` | int | |
| `whisky_id` | fk | что участник считает этим образцом |
| `submitted_at` | datetime | null пока черновик |

Уникальность: `(participant_id, round, sample_no)` — один ответ на образец,
и `(participant_id, round, whisky_id)` — одно название нельзя поставить дважды.
После `submitted_at` правки запрещены. Закрытие раунда проставляет
`submitted_at` всем оставшимся черновикам: забытая кнопка «Отправить»
не должна стоить человеку целого раунда.

### `rating` — личная оценка образца

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `participant_id` | fk | |
| `sample_no` | int | оценивается образец, а не название: в момент оценки участник ещё не знает, что налито |
| `score` | int | 0–100 |
| `tags` | json | теги вкуса и аромата |

### `result` — посчитанные итоги

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `participant_id` | fk pk | |
| `points_nose`, `points_palate`, `points_partial`, `points_bonus` | int | слагаемые видны отдельно — так проверяется вручную |
| `total` | int | |
| `place` | int | |
| `computed_at` | datetime | |

Таблица — кэш, а не источник истины: пересчитывается из `answer` целиком по кнопке.

### `delivery` — отметка об отправленном сообщении

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `id` | int pk | |
| `participant_id` | fk | |
| `kind` | text | пока только `results` |
| `sent_at` | datetime | |

Уникальность: `(participant_id, kind)`. Пишется **только успешная** отправка —
поэтому повторное нажатие «разослать» догоняет тех, кому не дошло, и никому
не шлёт второй раз.

### `ai_cache` — кэш ответов модели

| Поле | Тип | Пояснение |
| --- | --- | --- |
| `key` | text pk | нормализованное название или sha256 изображения |
| `kind` | text | `text` или `image` |
| `payload` | json | разобранный ответ модели |
| `created_at` | datetime | |

Повторный запрос того же виски не идёт в API и не стоит денег.

### `admin_session`, `audit_log`

Сессии админки (токен, срок жизни) и журнал действий: кто открыл раунд, кто
пересчитал итоги, кто разослал сообщения. Журнал нужен, чтобы после вечера
можно было разобраться, что произошло.

## Правила целостности, которые важнее схемы

* ответы никогда не удаляются — пересчёт итогов всегда возможен заново;
* правильные соответствия «номер ↔ виски» не отдаются клиенту ни в каком виде,
  пока дегустация не в статусе `scoring` или `closed` — включая JSON-ответы,
  подсказки автодополнения и порядок элементов в списках;
* удаление дегустации каскадом удаляет участников, ответы и оценки, и требует
  подтверждения вводом названия.
